## Step Cadence Zero Log Review

- Goal: capture device logs and explain why simulated step cadence is zero during Xiaomi Health route mock.
- Evidence: full logcat saved to `/tmp/portalex-step-logcat-20260524.txt`; connected device is Xiaomi `23113RKC6C`, Portal pid `13812`, Xiaomi Health pids `30758` and `18837`, system_server pid `14343`.
- Logs show Xiaomi Health foreground activity and available `step_detector`/`step_counter` sensors in `dumpsys sensorservice`, but no Portal `Register step sensor` or `Started synthetic step events` entries in the captured window.
- Root cause found in code: `MockServiceHelper.setSpeed()` wrote `speed` as a Float, while Xposed `RemoteCommandHandler` reads `set_speed` with `Bundle.getDouble("speed", 0.0)`. Route mock calls `setSpeed()` every tick, so the remote `FakeLoc.speed` was reset to `0.0`; automatic step cadence therefore computed `0` steps/min.
- Fix: `MockServiceHelper.setSpeed()` now writes `speed` using `putDouble`.
- Follow-up: install the fixed APK, restart scoped apps/LSPosed target processes if needed, rerun route mock, and confirm logs include step sensor registration plus nonzero speed.
