## 修复路线模拟速度波动为 0 时注入崩溃

- 目标/问题：修复路线模拟中 `speedAmplitude = 0.0` 表示禁用速度波动时，Xposed 注入侧仍调用 `Random.nextDouble(-0.0, 0.0)` 导致 `IllegalArgumentException: Random range is empty`、位置注入链路中断的问题。
- 改动范围：
  - `xposed/src/main/java/moe/fuqiuluo/xposed/BaseLocationHook.kt`
  - `xposed/src/test/java/moe/fuqiuluo/xposed/BaseLocationHookSpeedTest.kt`
  - `docs/context/2026-05-29.md`
- 设计决定：
  - 在 `BaseLocationHook.kt` 中抽出 package/internal 级纯函数 `calculateInjectedSpeed(speed, speedAmplitude)`，便于 JVM 单元测试，不改变 `MockServiceHelper`、路线 UI 或远端命令协议。
  - 当 `speedAmplitude <= 0.0` 时速度扰动直接为 `0.0`，保留路线模拟禁用速度波动的既有语义，并避免 Kotlin `Random.nextDouble(from, until)` 空区间异常。
  - 当 `speedAmplitude > 0.0` 时继续使用原区间 `[-amp, amp)`，并保留最终速度 `coerceAtLeast(0.1)` 的既有保护。
  - 未补充 `FakeLoc.moveLocation()` 回归测试，避免在本次路线速度崩溃修复中扩大范围；核心崩溃已由纯速度计算测试覆盖。
